## Summary
- Add merchant dashboard page `/catalog-intelligence` for catalog group management (Phase 2).
- Wire typed API client to Phase 1 backend endpoints: groups, items, relations, rankings, and tenant settings.
- Add sidebar navigation and ar/en i18n — no AI runtime wiring in this PR.

## Why
Phase 1 laid the data model and backend APIs. Merchants need a UI to define product groups, membership, alternatives, and best-seller flags before Phase 3+ consumes structured catalog evidence in the AI pipeline.

## Scope
### In scope
- `dashboard/src/api/catalogIntelligence.ts` — typed client
- `dashboard/src/pages/CatalogIntelligence.tsx` — groups, settings, uncategorized tabs
- Route, sidebar entry, i18n (ar/en/types)

### Out of scope
- AI browse scope resolver / pipeline wiring (Phase 3)
- Product card filtering (Phase 4)
- Best sellers / alternatives runtime usage (Phase 5)
- Telemetry (Phase 6)
