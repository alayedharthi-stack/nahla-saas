## السبب المثبت ونطاق اليقين

1. الشاشة تقرأ البيانات عند الفتح وتغيير الفترة فقط. زيادة السجل بعد فتح الشاشة
   لا تطلق قراءة أخرى. هذا هو أول انقطاع **في إعادة الإنتاج المحلية**: الاستهلاك
   يصل إلى السجل، والتجميع وAPI يرتفعان، لكن الشاشة تحتفظ بالقراءة السابقة.
2. فشل إحدى قراءتي API لا يعالج، ثم ينتهي التحميل وتستخدم البطاقات `?? 0`، أو
   تحتفظ بقراءة سابقة. النتيجة صفر مضلل أو رقم قديم بلا بيان للفشل.
3. السجل لا يمنع إعادة إدراج response ID نفسه. إعادة تسجيل الحدث تضاعف التكلفة.
4. تسعير Haiku 4.5 يستخدم سعر Haiku 3.5: 0.80/4 دولار بدل 1/5 دولار لكل مليون
   رمز إدخال/إخراج. Opus 4.6 و4.8 يستخدمان 15/75 بدل 5/25 دولار.
5. التكلفة المسماة «فعلية» هي تكلفة محسوبة من رموز فعلية، وليست مبلغًا أعاده
   المزود. كما كانت أعداد الدورات والأفعال تجمع كل التاريخ بينما التكلفة ضمن
   الفترة المختارة، ولم يكن هناك حد علوي يمنع سجلات ذات تاريخ مستقبلي.

## خطة السجلات القديمة — للمراجعة فقط

1. استكمال القراءة المصادق عليها: تشغيل أداة audit بالاتصال المخصص الآمن، ومقارنة
   آخر خمس دورات لكل تاجر مع عدد صفوف الاستخدام ورموزها وإصدار تسعيرها، ثم GET
   استجابة لوحة المالك للفترة نفسها. لا يعد القبول أو الإرسال دليلًا بديلًا عن
   سجل التكلفة.
2. استخراج manifest للمراجعة: هوية الحدث، التاجر، الرموز المسجلة/المقدرة، cache،
   إصدار السعر الأصلي، التكلفة الأصلية، السعر الصحيح الساري في تاريخ الاستهلاك،
   التكلفة المرشحة والفارق. الاحتفاظ بالقيم الأصلية وعدم تسعير كل الماضي بسعر اليوم.
3. مجموعة provider + response ID المتكررة لا تُحذف تلقائيًا. التحقق من تطابق
   التاجر والنموذج والرموز وتفاصيل cache قبل اقتراح أي تسوية. التعارض في نسبة
   الحدث يوقف المعالجة. NULL لا يتيح إزالة التكرار بالاعتماد على turn ID: الدورة
   الواحدة قد تحتوي عدة استدعاءات مدفوعة.
4. عدم اختراع usage أو تكلفة مزود غير موجودة. السجلات دون رموز فعلية تبقى
   تقديرات، والأسعار المؤقتة تبقى واضحة. لا يعاد نسب حدث غير معروف لتاجر بالتخمين.
5. تقديم manifest وأثر قبل/بعد ومصالحة فاتورة المزود إن توفرت، وحفظ نسخة قبل
   التغيير وخطة رجوع، والحصول على اعتماد منفصل قبل أي تنفيذ إنتاجي.
6. بعد معالجة التكرارات وفق اعتماد منفصل، مراجعة تطبيق 0114 في نافذة مناسبة؛
   إنشاء الفهرس العادي قد يقفل الكتابة أثناء البناء. لن تُنشأ فهارس جديدة على
   الجدول الموجود بمجرد `create_all`، لذا يلزم تطبيق migration المقصود؛ النشر
   دونها لا يضمن منع التكرار. إعادة فحص التاجرَين بقراءة آمنة بعد أي اعتماد لاحق.

لم تُنفَّذ هذه الخطة، ولم يُبنَ أمر يغيّر السجلات القديمة أو إعدادات الإنتاج.
