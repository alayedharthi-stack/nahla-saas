## Summary
- Add Phase 1 Catalog Intelligence foundation: relational data model for product groups, group membership, product relations, and rankings.
- Add merchant-scoped backend APIs for CRUD on groups/items/relations/rankings plus tenant catalog settings.
- Add read-only service helpers for future brain runtime consumption without wiring AI/WhatsApp in this PR.

## Why
Nahla needs a platform-wide catalog taxonomy layer so merchants can define product groups, alternatives, and best sellers before AI browse scope uses structured evidence instead of guessing from titles or stale focus.

This PR is intentionally limited to **data model + backend APIs**. It does not include dashboard UI, AI runtime wiring, or commerce safety boundary changes.

## Scope
### In scope
- Migration `0083` — `product_groups`, `product_group_items`, `product_relations`, `product_rankings`
- SQLAlchemy models
- `merchant_catalog_settings` parser (`store_settings["catalog_intelligence"]`)
- `catalog_intelligence_service` CRUD + read-only helpers
- Router `/settings/catalog-intelligence` and `/catalog-intelligence/*`

### Out of scope
- Dashboard UI
- AI pipeline / WhatsApp runtime integration
- Honey-only or merchant-specific hardcoding
- Phase 3+ browse scope resolver / product card filtering
